# Project notes

This app runs with the public TanStack Start, Vite, and Nitro packages.

The storefront brand is **Velvetique Beauty**. Older database copy still says **63rd Street Apothecary** (`supabase/README.md`, the SQL defaults, and the `63rd` browser storage prefix).

## What the app is

A server-rendered shop with a customer storefront and an admin area.

- Shoppers browse products, search, add to cart, save a wishlist, and check out.
- Without `DATABASE_URL`, the catalog is the local sample data in `src/lib/products.ts`. Pages still render.
- With `DATABASE_URL`, server functions in `src/server/` read and write Postgres through Drizzle (`src/db/schema.ts`). Auth is a cookie session named `63rd_session`. Checkout writes a pending order. No card processor is connected.
- Cart, wishlist, addresses, and recent views also persist in `localStorage` under keys prefixed with `63rd-`.
- `src/lib/supabase.ts` and `supabase/` are an earlier Supabase schema. The storefront loader does not call that client.

## Stack

| Piece | Role |
| --- | --- |
| React 19 | UI |
| TanStack Start + TanStack Router | File routes, SSR, server entry |
| TanStack Query | Query client on the router context |
| Vite 8 | Dev server and build. `@/` aliases come from `tsconfig.json` via `resolve.tsconfigPaths` |
| Nitro | Production server bundle (`vite build` only) |
| Tailwind CSS 4 | Styling, via `@tailwindcss/vite` |
| Radix UI + shadcn-style components | `src/components/ui` |
| Drizzle + `postgres` | Server-side catalog, accounts, and orders when `DATABASE_URL` is set |
| Vitest | Route and checkout tests |

`supabase/` and `src/lib/supabase.ts` are leftover from the earlier hosted-auth design. New server code uses `src/db` and `src/server`.

## Directory map

```
src/routes/            File routes. One .tsx file per URL. Do not add a pages/ or app/ folder.
src/routeTree.gen.ts   Generated by the TanStack router plugin. Do not edit by hand.
src/router.tsx         Creates the router and QueryClient.
src/start.ts           Request middleware: SSR error page + CSRF on server functions.
src/server.ts          Server fetch entry. Turns swallowed SSR 500s into an HTML error page.
src/components/site/   Storefront chrome: header, footer, cart, product cards, search.
src/components/admin/  Admin product editor and gate.
src/components/ui/     Shared UI primitives.
src/lib/products.ts    Local catalog used when Postgres is not configured.
src/lib/storefront.ts  Loads the catalog from a server function, or falls back to the local catalog.
src/lib/store.tsx      Cart, wishlist, coupon, reviews, and checkout state.
src/lib/api.ts         Catalog and cart helpers used by the UI.
src/lib/auth.tsx       Client auth context. Calls server functions for sign-in and session.
src/lib/checkout.ts    Validates the checkout payload.
src/server/            Server functions: catalog, session cookie, orders, admin.
src/db/schema.ts       Drizzle schema for Postgres.
src/db/client.ts       Opens a Drizzle client from DATABASE_URL.
src/db/seed.ts         Sample catalog, coupons, reviews, and an admin user.
src/styles.css         Tailwind entry and theme tokens.
supabase/              Earlier Supabase SQL. Not used by the current storefront loader.
public/                Static files such as the logo and robots.txt.
```

Route file names use TanStack's flat convention: `product.$slug.tsx` is `/product/:slug`, and `admin.orders.$id.tsx` is `/admin/orders/:id`. `src/routes/README.md` has the full naming rules.

## Run it locally

Requirements: Node.js 22 or newer, and npm.

```sh
npm install
npm run dev
```

Open [http://localhost:8080](http://localhost:8080).

You do not need a database to click through the shop. Leave `DATABASE_URL` unset and the pages use the sample catalog in `src/lib/products.ts` plus `localStorage`. Sign-in and saved orders need Postgres.

### Optional: live data

`docker-compose.yml` starts Postgres 16 as user `apothecary`, database `apothecary`, on port **5440** (5432 is often already taken on this machine).

```sh
docker compose up -d
```

Put this in `.env.local` (do not commit it):

```
DATABASE_URL=postgresql://apothecary:apothecary@localhost:5440/apothecary
```

Then create the tables and load the sample catalog:

```sh
npm run db:push
npm run db:seed
```

Restart `npm run dev` after changing env files. Vite does not replace a `DATABASE_URL` that is already set in the process environment. Copy the values from `.env.example`.

## Deploy note

To deploy to Cloudflare, Vercel, or Netlify, set Nitro's preset for that host (for example `NITRO_PRESET=cloudflare-module`) before `npm run build`. The custom server entry is `src/server.ts`, configured in `vite.config.ts` as `tanstackStart.server.entry`.
